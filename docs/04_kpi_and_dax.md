## 01 Volume

### Total Incidents

Distinct incidents. Counted at case grain, never event grain - the event table holds 141,707 rows for 24,918 incidents, so counting there would overstate volume roughly 5.7x.

```dax
Total Incidents =
COUNTROWS ( fact_incident_case )
```

Format string: `#,0`

### Total Events

Process steps recorded across all incidents.

```dax
Total Events =
COUNTROWS ( fact_incident_event )
```

Format string: `#,0`

### Avg Events per Incident

Process touch count. A rising value means more handling per incident.

```dax
Avg Events per Incident =
DIVIDE ( [Total Events], [Total Incidents] )
```

Format string: `#,0.0`

## 02 SLA

### SLA Met

Incidents whose final observed made_sla value was true. Last-value semantics per DQ-09.

```dax
SLA Met =
SUM ( fact_incident_case[is_sla_met] )
```

Format string: `#,0`

### SLA Breached

Incidents whose final observed made_sla value was false.

```dax
SLA Breached =
SUM ( fact_incident_case[is_sla_breached] )
```

Format string: `#,0`

### SLA Attainment %

Headline KPI. Denominator is ALL incidents, not just resolved ones - excluding unresolved incidents would flatter the number by hiding the cases most likely to have breached.

```dax
SLA Attainment % =
DIVIDE ( [SLA Met], [Total Incidents] )
```

Format string: `0.0%`

### SLA Breach %

Complement of attainment. Held as its own measure so breach-focused visuals do not have to express 1 - x.

```dax
SLA Breach % =
DIVIDE ( [SLA Breached], [Total Incidents] )
```

Format string: `0.0%`

### SLA Attainment % PM

Prior-month attainment. Requires dim_date to be marked as the date table.

```dax
SLA Attainment % PM =
CALCULATE ( [SLA Attainment %], DATEADD ( dim_date[Date], -1, MONTH ) )
```

Format string: `0.0%`

### SLA Attainment % MoM

Month-over-month change in percentage points. Returns blank rather than a misleading full-value delta when there is no prior month.

```dax
SLA Attainment % MoM =
VAR Current = [SLA Attainment %]
VAR Prior = [SLA Attainment % PM]
RETURN IF ( NOT ISBLANK ( Prior ), Current - Prior )
```

Format string: `+0.0%;-0.0%;0.0%`

## 03 Cycle Time

### Incidents with Valid Cycle Time

The cycle-time denominator. Shown on the report so the audience can see how many incidents the duration KPIs are actually based on.

```dax
Incidents with Valid Cycle Time =
SUM ( fact_incident_case[has_valid_resolution_time] )
```

Format string: `#,0`

### Median Resolution Hours

Primary cycle-time KPI. Median rather than mean: the distribution has a long right tail, and the mean (178h) is over eight times the median (22h), so a mean would describe almost no real incident.

```dax
Median Resolution Hours =
CALCULATE (
    MEDIAN ( fact_incident_case[Resolution Hours] ),
    fact_incident_case[has_valid_resolution_time] = 1
)
```

Format string: `#,0.0`

### Avg Resolution Hours

Retained alongside the median so the skew is visible rather than hidden.

```dax
Avg Resolution Hours =
CALCULATE (
    AVERAGE ( fact_incident_case[Resolution Hours] ),
    fact_incident_case[has_valid_resolution_time] = 1
)
```

Format string: `#,0.0`

### Median Resolution Days

Same measure in the unit business stakeholders tend to think in.

```dax
Median Resolution Days =
DIVIDE ( [Median Resolution Hours], 24 )
```

Format string: `#,0.0`

### P90 Resolution Hours

Tail risk. The median describes the typical incident; P90 describes the experience that generates escalations.

```dax
P90 Resolution Hours =
CALCULATE (
    PERCENTILE.INC ( fact_incident_case[Resolution Hours], 0.9 ),
    fact_incident_case[has_valid_resolution_time] = 1
)
```

Format string: `#,0.0`

## 04 Bottleneck

### Total Dwell Hours

Total elapsed time accumulated in the filtered states. Nulls (the final event of each case, which has no successor) are ignored by SUM, which is the correct behaviour - that time is genuinely unmeasured, not zero.

```dax
Total Dwell Hours =
SUM ( fact_incident_event[Dwell Hours] )
```

Format string: `#,0`

### Avg Dwell Hours

Mean time an incident sits in a state before moving on.

```dax
Avg Dwell Hours =
AVERAGE ( fact_incident_event[Dwell Hours] )
```

Format string: `#,0.0`

### Median Dwell Hours

Typical dwell. Diverges sharply from the mean in the Active state, which is the signal that a minority of incidents are stalling there.

```dax
Median Dwell Hours =
MEDIAN ( fact_incident_event[Dwell Hours] )
```

Format string: `#,0.0`

### Waiting Hours

Elapsed time blocked on a third party: user, vendor, problem or evidence.

```dax
Waiting Hours =
CALCULATE ( [Total Dwell Hours], dim_state[State Category] = "Waiting" )
```

Format string: `#,0`

### Working Hours

Elapsed time in New or Active, where the resolver team holds the work.

```dax
Working Hours =
CALCULATE ( [Total Dwell Hours], dim_state[State Category] = "Working" )
```

Format string: `#,0`

### Waiting Time %

Share of elapsed time the process is blocked. Separates a capacity problem (fix by adding people) from a dependency problem (fix by changing the process).

```dax
Waiting Time % =
DIVIDE ( [Waiting Hours], [Total Dwell Hours] )
```

Format string: `0.0%`

### % of Total Elapsed Time

Each state's share of total elapsed time. REMOVEFILTERS only on dim_state so the denominator still respects date and priority slicers - the ratio stays meaningful inside any filtered view.

```dax
% of Total Elapsed Time =
DIVIDE (
    [Total Dwell Hours],
    CALCULATE ( [Total Dwell Hours], REMOVEFILTERS ( dim_state ) )
)
```

Format string: `0.0%`

### Happy Path %


Format string: `0.0%`

Share of volume on the five dominant paths - the standardised core of the process.

```dax

DIVIDE (

)
```

Format string: `0.0%`
